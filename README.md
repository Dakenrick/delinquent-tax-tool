# Delinquent Tax Research Tool

A $0-to-run tool that scrapes county delinquent tax (real property + mobile
home) lists on a schedule and serves the results as JSON, with a static
frontend to filter/map them. No server, no database — just GitHub Actions
(scraping) + GitHub Pages (hosting).

## How it's organized

```
scrapers/
  dorchester_sc/
    scrape.py            <- one scraper per county
data/
  dorchester_sc/
    real_property.json   <- generated by the scraper, committed by Actions
    mobile_homes.json
  counties/
    dorchester_sc.json    <- hand-maintained: sale date, registration window,
                              advertising windows. NOT scraped — county
                              publishes these as plain text/PDF, not a table.
.github/workflows/
  scrape-dorchester.yml   <- runs scrape.py daily, commits changes
requirements.txt
```

## Running a scraper locally

```bash
pip install -r requirements.txt
python scrapers/dorchester_sc/scrape.py
```

This writes/overwrites the JSON files under `data/dorchester_sc/`. Each
output file includes:
- `records`: the actual parsed rows (name, parcel ID or sticker #, balance
  due, prior years unpaid, any "formerly owned by" history)
- `record_count`, `site_reported_total_accounts`,
  `site_reported_total_balance_due`, `parsed_total_balance_due`,
  `totals_match` — a built-in sanity check. If `totals_match` is `false`,
  the site's own footer total doesn't match what we parsed, which usually
  means the page's HTML structure changed and the parser needs a look.

## Adding a new county

1. Make a new folder under `scrapers/<county_state>/` with its own
   `scrape.py`. Every county publishes this data differently (HTML table,
   PDF, ArcGIS portal, etc.), so this is genuinely custom work per county —
   there's no universal parser possible here.
2. Add a `data/counties/<county_state>.json` file with the sale date,
   registration window, and any other dates the county publishes as text
   rather than as structured data.
3. Add a workflow (or extend an existing one) under `.github/workflows/`
   to run it on a schedule.
4. Point the frontend's county list at the new data files.

## Cost

- GitHub Actions: free, unlimited minutes on public repos.
- GitHub Pages: free static hosting.
- No database, no server, no paid API calls.

## A note on scope

This project only scrapes public government data sources (county tax
offices) directly. It does not pull from Zillow, Redfin, or Land.com —
none of those offer a free or ToS-compliant way to do that programmatically.
